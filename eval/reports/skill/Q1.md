# IDEA_REPORT：LLM Agent 经验记忆的自动发现与修订

日期：2026-11-16 ｜ 状态：查新通过（三轮，范围=arXiv 标题/全文检索，未覆盖 ACL Anthology 外数据库）

## 1. 真实应用任务（§1.1 反向追问结论）

长期运行的 LLM agent（个人助理、运维/oncall agent、GUI/网页操作 agent）跨会话积累三类经验条目：技能（skill/流程）、教训（failure note）、环境知识（事实）。真实约束：环境持续漂移（软件版本、价格、权限、组织人事），条目会过时、互相冲突、因 agent 自身错误推理而带病积累。决策点：每条记忆是否仍可信、能否继续被检索使用——现有系统默认"写入即正确、只增不改"。

## 2. 代表性工作与默认条件（论文事实）

- **A-MEM**（arXiv:2502.12110, NeurIPS 2025）：新记忆到达时触发相似历史条目的属性更新。默认条件：①修订由"新观察"驱动（reactive）；②冲突会在相似度检索中暴露。
- **STALE/CUPMem**（arXiv:2605.06527）：指出隐式冲突问题（新证据不显式否定旧记忆），benchmark 400 场景；CUPMem 在**写入时**做结构化状态整合与传播式修订，最优模型仅 55.2%。默认条件：冲突证据最终会到达并被写入路径撞上；任务是单用户个性化记忆。
- **AMA**（arXiv:2601.20352）：检索时由 Judge 检测逻辑冲突、Refresher 定点更新/删除。默认条件：冲突在**被检索到**时才被检查（retrieval-triggered）；无全库审计。

**哪个条件在真实场景不成立**（我方假设）：漂移产生的"沉默过期"——事实变了但新证据永远不会再被观察到（agent 不再访问该页面/该 API），此时 write-time 与 retrieval-time 机制双双失效，错误条目永久存活。其次，agent 自身错误动作产生的假记忆没有"新观察"来纠正它。第三，现有评测（MemBench, arXiv:2506.21605；LoCoMo/LongMemEval）只测静态检索问答，不测漂移下的端到端任务成功率与修订编辑质量。

## 3. 候选研究问题与差异

**RQ**：能否在**无新冲突证据到达**时，主动发现并修订经验记忆中的过期/错误条目？

方法草图（proactive memory audit）：离线/低频审计循环——①风险排序：按条目年龄、最后支持时间、跨条目蕴含矛盾、被检索后导致失败的 trace 打分，选 top-k；②取证验证：用 agent 现有工具对条目做低成本主动探针（重新查询环境）+ 跨条目一致性对检；③带溯源的修订：update/invalidate/merge，保留证据指针；④编辑预算受控。

与最近工作的差异（我方假设，待正文精读复核）：对 CUPMem——其在写入路径上做状态裁决，且面向对话个性化；我们做面向任务执行 agent 的全库、预算受限、取证式审计，覆盖"证据永不到达"的沉默过期。对 AMA——其冲突检测绑定检索时刻、只对被召回候选生效；我们解耦检测与使用，编辑带 provenance 可审计。对 A-MEM——其"记忆演化"由新记忆触发且不改真值，我们显式判定真值与可用性。

## 4. 待验假设

- H1（假设）：仅基于静态特征（年龄/矛盾/失败关联）的风险排序即可让审计的编辑召回率显著高于随机，且探针成本低于全量重验。
- H2（假设）：沉默过期条目存在可观比例（>20% 的过时无新证据碰撞），reactive 基线对其召回≈0，主动探针可召回大部分。
- H3（假设）：带溯源修订提升长周期任务成功率，且代价（探针数/token）低于"定期清空重积累"。

## 5. 最小实验（验证路径）

环境：合成漂移环境——LLM 生成一个"公司知识库/网店目录"世界（200–500 条可验证事实），提供只读查询工具；按剧本改 30–50% 事实（一半设为沉默过期），事实真值有 oracle。

流程：memory-augmented ReAct agent 跑 30 个会话积累记忆 → 注入漂移 → 继续跑任务。

三个臂：①append-only 基线；②写入时冲突检查（简化 CUPMem 式）；③②+主动审计模块。

指标：任务成功率随时间变化；记忆精度（现存真条目占比）；编辑精确率/召回率对 oracle；探针与 token 成本。预算：纯 API、约 1–2 周单人。
