# Q2 选题报告：自进化 agent 的"真变强"评测

**真实应用任务**：允许 agent 持续修改自身代码/提示词/配置（技能库、记忆、策略）的长期部署系统。真实任务是"持续自我改进且不悄悄变坏"，而非一次性刷榜。[我方假设]

**已有工作对照（查新核实）**：
- **Voyager**（2023）：技能库自进化，指标为零样本迁移增益；默认单调变好、不测回归。[论文事实]
- **EvoPathBench**（2026）：冻结 checkpoint 测 held-out 泛化与 retention（退化）；对"评测集被进化过程污染"仅以 held-out 缓解，未系统化。[论文事实]
- **EvoAgentBench**（2026）：528 训/267 测隔离协议并报告负迁移；但评测集静态、无刷新，退化只作现象不检测。[论文事实]
- **Benchmark Self-Evolving**（2024）：静态评测集重构后多数 LLM 成绩下滑——证实"固定集高估"。[论文事实]

**默认条件 vs 真实部署缺口**：①评测集静态且假设进化者不可见（真实部署中 agent 会读到/记住评测痕迹）；②假设改进单调、只报平均增益（真实部署存在静默退化，影响存量任务）；③只评进化终点（真实部署关心整条轨迹）。三者均可能不成立。[我方假设]

**候选研究问题**：持续自进化场景下，如何设计单一评测协议，同时给出（a）未被污染的泛化增益与（b）轨迹级回归检测？

**待验假设**：
- H1：防污染的刷新评测下，宣称的进化增益显著缩水。
- H2：静默退化集中于少数进化步，endpoint-only 评测会漏检。
- H3：双侧协议成本远低于重建评测集。[均为我方假设]

**与最近工作的差异**：EvoPathBench 只测记忆进化退化、EvoAgentBench 用静态集且只报退化不检测；本工作把"防污染（刷新/派生评测）"与"防退化（轨迹级回归）"合一为单一协议，且面向"修改自身代码"这一最强自进化设定。[论文事实+我方假设]

**最小实验**：基于 EvoAgentBench 开源协议接入一个记忆型 agent，每 k 步冻结 checkpoint：(a) 原始 held-out 集 + LLM 重构的"刷新变体"双轨评分；(b) 一组核心回归任务贯穿全程。指标：刷新前后 Δ 增益、退化步检出率/漏检率。规模：单域、≤30 进化步、3 种子。[已实现机制：仅设计，未运行]
