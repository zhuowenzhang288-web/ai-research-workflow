# IDEA_REPORT：LLM Agent 经验记忆的自动发现与修订

（查新：arXiv 检索 8 组关键词并逐条核实；机制为摘要级论文事实，差异与空白为我方判断。）

## 1. 真实应用任务
长周期 LLM agent（软件工程、运维、科研助手）持续积累"经验条目"：技能、教训、环境知识（Voyager 式技能库、Reflexion 式教训、Mem0/MemoryBank 式事实）。这些条目随依赖升级、接口变更而过时、冲突、积累错误——如记住的 API 用法已废弃、旧教训适得其反。

## 2. 代表性对照工作
- **MemoryBank**（arXiv:2305.10250）：艾宾浩斯曲线时间衰减 + 写入时 LLM 判断更新。
- **A-MEM**（arXiv:2502.12110, NeurIPS'25）：新记忆写入时驱动语义相关旧记忆"演化"改写。
- **PACMI**（arXiv:2610.05732, 2026-10）：溯源图 + 四态有效性格，新证据到达时沿依赖边级联失效。
- 同集群：**MemGuard**（2608.21867，依赖验证器信号）、**Memory Worth**（2604.12007，需成败标签）。

## 3. 默认条件中哪个不成立
上述方法默认：① 漂移以**显式新证据**或**验证器信号**形式到达（PACMI/MemGuard/Memory Worth）；② 或靠**写入瞬间的 LLM 语义判断**（Mem0/A-MEM），事后无审计。真实场景常不成立：多数环境无 reward/验证器；新信息零散隐含在轨迹里，漂移不可观测；写入时判断漏掉"当时正确、后来过时"的条目。

## 4. 候选研究问题
**在无显式新证据、无验证器信号下，如何从 agent 自身轨迹的一致性信号（条目使用结果、条目间互证/互斥）自动定位过时或冲突条目，并完成修订（改写/合并/废弃）？**

待验假设（我方推测）：
- H1：条目使用后的任务结果构成弱监督信号；"曾成功、现失败"或与新观察互斥的条目大概率过时。
- H2：基于该信号的"发现→修订"闭环，在漂移后恢复成功率，优于无修订、时间衰减、仅抑制检索三种基线。
- H3（反向）：THEANINE（arXiv:2406.10996）主张保留过时记忆作演化线索——修订（尤其删除）可能损害需历史上下文的任务。

## 5. 与最近工作的差异
- vs PACMI：不靠显式新证据与溯源图，信号来自轨迹结果一致性。
- vs MemGuard：不依赖外部验证器，用任务成败作弱信号。
- vs Memory Worth：它做检索抑制/废弃；我们做条目级发现 + 语义修订，并验证"修订优于仅抑制"。
- vs A-MEM/Mem0：它们写入瞬间触发修订；我们做事后全局审计，覆盖"写入时正确、后来过时"的条目。

## 6. 最小验证路径（单环境，1 人周量级）
1. 造漂移环境：基于现成 agent 环境（SWE 类/终端类），选定 K 个可漂移事实（命令用法、配置路径、版本行为），注入一次"环境变更"。
2. 先在旧环境跑 ~100-200 任务沉淀经验库（Reflexion 式教训 + 事实条目，约 100 条）。
3. 注入漂移后比较四组：a) 无修订 b) 时间衰减 c) 仅抑制检索 d) 我们的发现+修订闭环。
4. 指标：漂移后任务成功率（主）；过时条目发现 F1、修订准确率（次）。
5. 规模：单环境、单次漂移、≥3 次重复；仅当 d 显著优于 b/c 且 H3 受控时结论成立。

风险：成败信号噪声大（H1 可能不成立），届时降级为"发现+人工确认修订"。
