## 五、必须诚实声明的几点

1. **judge 不是完全盲**：skill 臂的报告带其特征词汇（"IDEA_REPORT""论文事实/假设""查新三轮"），
   judge 可能认得出哪份是 skill 产出。不过这些"特征"本身就是 skill 在起作用——它强迫 agent
   用证据标签结构输出。所以这不是作弊，但要如实说明。
2. **防编造不是 skill 的卖点**：换个底座（如纯文本 LLM 不带联网工具）或换更会编的模型，
   skill 的"查不到就写查不到"纪律才可能显出防编造价值。本设置下两臂都 0 编造，测不出。
3. **F2（VQA SOTA 数字）不可行**：本网络不通 arxiv.org 正文页，两臂都卡死，已记录排除。
4. **F3 首次 noskill 超时**（15 分钟没跑完，卡在分块下载），重跑成功；skill 一次跑完。
   这提示 skill 可能有"更高效执行"的边际作用，但 n=1 不作结论。
5. **n=7，单一 judge 家族**，结论是"强初步证据"，不是统计显著。

## 六、对 GitHub 发布的建议

**可以发。** 主要卖点应是：**"这个 skill 让 agent 的科研产出更严谨、证据纪律更强、结构更完整"**，
而不是"防止编造"（那套说法在这个底座下站不住、也不诚实）。
