# 评测：这个 skill 到底有没有用

## 怎么做的

同一底座、同一个模型，**唯一变量是加载不加载 `SKILL.md`**。

| 项 | 设置 |
|---|---|
| 底座 | OpenCode 1.19.5 |
| 模型（两臂相同） | kimi-k3（通过自建 OpenAI 兼容网关） |
| 变量 | `opencode.json` 里 `instructions` 是否指向 `SKILL.md` |
| 任务 | 7 道（4 道质量题 Q1–Q4 + 3 道引用核验探针 F1/F3/F4） |
| 预算 | 每题 15 分钟硬超时 |
| 评审模型 | deepseek-v4-pro（与 kimi-k3 不同模型家族） |
| 评审方式 | 两臂产物**直接对抗**（head-to-head），报告顺序随机打乱后盲评 |

14 份报告、55 条引用全部用 arXiv 官方 API 回查编号与标题：**两臂均 0 条编造引用，HR = 0.0%**。

## 这说明了什么、没说明什么

**说明**：这个 skill 主要提升的是**查新严谨度**（+10）和**证据纪律**（+11）——即让 agent
主动对照已有工作、标注检索范围与待核验项、区分"论文事实/我方假设/实验结果"。
这两项正好是 SKILL.md 里写得最重的部分。

**没说明**（重要）：

1. **没有测出"减少编造"的增益**——因为两臂都没有编造可减。kimi-k3 本身带联网工具、会主动核验引用。
   换个不带工具或更容易编的底座，skill 的"查不到就写查不到"纪律才可能显出价值。**此项未验证。**
2. **judge 不是完全盲**——skill 产物带特征词（"IDEA_REPORT"、"论文事实/假设"、"查新三轮"），
   评审模型可能认得出哪份来自 skill。这些特征本身是 skill 起作用的表现，但需如实说明。
3. **n=7，单一评审模型**，属强初步证据，不是统计显著。
4. **F2 题（VQA SOTA 数字）因网络不通 arXiv 正文页，两臂均失败**，已排除。

## 复现

```bash
export AGENT_API_KEY=...          # 被测模型网关 key
export JUDGE_API_KEY=...          # 评审模型 key
export JUDGE_GATEWAY=https://your-gateway/v1/chat/completions

# 1. 准备两臂配置（各自目录下放 opencode.json，skill 臂加上 instructions）
# 2. 跑一道题（两臂）
./run_arm.sh noskill Q1
./run_arm.sh skill   Q1
# 3. 盲评
python3 judge_h2h.py tasks/Q1.md arm-noskill/Q1/IDEA_REPORT.md arm-skill/Q1/IDEA_REPORT.md out.json
# 4. 客观核验引用
python3 ../scripts/verify_citations.py arm-skill/Q1/IDEA_REPORT.md
```

`reports/` 是全部 14 份原始产物，`results/` 是 7 份 judge 评分 JSON。
