# Q2 选题报告：Agent 自进化的评测

## 1. 任务定位与对照工作

真实场景：部署中的软件工程/ML 工程 agent 持续处理新任务，并被允许自改代码、提示词与配置。代表性"自进化"工作均以静态基准上的分数增益作为"变强"的证据：

- **Darwin-Gödel Machine (DGM)**：archive 式开放进化，自改 coding agent 代码，报告 SWE-bench 20.0%→50.0%、Polyglot 14.2%→30.7%（arXiv 2505.22954）。
- **Live-SWE-agent**：边解真实 issue 边在线改写自身 scaffold，报告 SWE-bench Verified 77.4%、SWE-bench Pro 45.8%（arXiv 2511.13646）。
- **Artifact-to-Capability**（arXiv 2611.04952，2026.11）：受控五子棋环境中证明 Reflexion/Voyager/DGM 都满足"产物累积、行为改变、指标上升"三信号，却各自存在能力形成断裂（legalization gain、compositional override、loss-only drift）。

（以上均经网络检索确认。）

## 2. 现有评测默认了什么、何处不成立

1. **基准固定且与部署同分布**——不成立。进化循环反复在同一任务集上试错+选代，存在 in-loop 过拟合；真实部署任务流持续漂移（新 repo、新依赖、时间漂移、对抗用户）。
2. **分数=能力**——不成立。三信号已被证伪为能力的充分条件。
3. **评测器可信、反馈即时**——不成立。部署中反馈稀疏、延迟、有噪声；且自修改 agent 可能影响测量本身（改写 harness、选择性记忆），威胁模型不同。
4. **只测目标指标**——不成立。自修改可在未测维度（成本、时延、安全、其他能力面）引入未发现退化，而论文只报单一 resolve rate。

## 3. 研究问题、假设与差异

- **RQ1**：进化收益中有多少来自 in-loop 过拟合？定义指标 *evolutionary overfitting gap* = 循环内任务集增益 − 新鲜任务集增益。**H1**：gap 显著大于 0 且随代数扩大。
- **RQ2**：自修改引入的能力面退化如何被低成本检出？**H2**：目标指标上升的同时，未被反馈覆盖的能力面出现统计显著退化；**H3**：每代运行几十题的 held-out canary 电池即可检出大部分退化。
- **RQ3**：何种审计信息（lineage + 反事实重放）足以把增益归因于真实技能而非测试特定 hack。

**与最近工作的差异**：DGM/Live-SWE-agent 把基准分当结论，不分离循环内/外泛化、不测回归；Artifact-to-Capability 给出受控环境的定性诊断但无可迁移定量协议；本选题给出可执行的三电池评测协议与定量指标，并在真实 SWE 任务上验证。

## 4. 最小实验（验证路径）

用开源 DGM 代码（github.com/jennyzzt/dgm）+ 便宜档模型。SWE-bench Lite 切两半：50 题进进化循环作反馈源，50 题 held-out 测同分布泛化；SWE-bench Pro 取约 50 题测跨基准迁移（新鲜分布臂）；另配 40 题 canary 电池（HumanEval 子集 + 小型 repo 任务）测 facet 回归。跑 5 代，每代测三电池 + 成本/时延。指标：resolve rate、gap、回归率、成本曲线。预算：API 美元级、约一周。若 H1/H2 成立，即证明"假变强"真实且可测，为完整论文铺路。
