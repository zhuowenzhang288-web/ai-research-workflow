# Q1 选题报告：经验记忆的自动修订

## 1. 任务确认与对照工作
真实场景：长周期 agent（WebArena/WorkArena 办公自动化、OSWorld、长期个人助理）积累技能库、事实记忆、教训条目，而环境（UI、API、流程、偏好）持续漂移，条目随之过时、互相冲突、错误被固化。以下 3 个代表工作已用网络检索核对原文摘要：
- **Mem0**(arXiv:2504.19413)：新信息到来时由 LLM 判定对旧条目执行 ADD/UPDATE/DELETE，属"写入即修订"。
- **Zep/Graphiti**(arXiv:2501.13956)：时序知识图谱，新事实以失效边/有效期取代旧事实。
- **MemoryBank**(arXiv:2305.10250)：按遗忘曲线随时间与重要性衰减、降权。

## 2. 默认条件与真实场景的不成立处
- A（Mem0/Graphiti）：新观察必然到来且可信，可触发修订。真实中漂移常无人触发；且观测含幻觉/瞬时异常，据此"修订"会传播错误。
- B（Graphiti）：过时＝同实体出现新值。真实冲突常是多版本并存、跨任务教训误迁移、条目间相互依赖（改一条崩一片），非简单替换。
- C（MemoryBank）：过时与"旧"相关。漂移是内容性的：老条目可能仍正确，新条目可能即错，时间只是弱代理。
- D（三者共性）：修订＝局部覆盖、立即生效、无验证环节。技能类记忆实为程序/规则，直接改可能引入回归。

## 3. 研究问题、假设与差异
RQ：能否不依赖"新触发信息"，主动发现候选过时/冲突条目，并以低风险方式修订？
- H1：被后续成功轨迹反复"遵守则失败、忽略则成功"的条目，是高精度过期信号（基于使用证据，无需环境真值）。
- H2：发现与修订应解耦——发现靠轨迹审计，修订须通过影子回归才生效，可将错误修订率压低一个量级。
- H3：记忆库冲突密度随时间超线性增长，写入时判定错误率同步上升，说明需要独立于写入的修订机制。
与最近工作的差异：Mem0/Graphiti 为写入时被动修订、以"替换"为模型；遗忘曲线以时间为代理。本方向：主动审计＋证据化置信度＋把修订当作需检验的假设。

## 4. 最小实验（验证路径）
- 环境：WorkArena/WebArena 子集，注入两类受控漂移（改元素选择器/字段名；改流程步骤顺序）；漂移前跑基线 agent 攒约 100 条记忆。
- 管线：漂移后跑 20 轮任务 → 从轨迹挖掘否定/支持信号 → 生成修订（删/改/合并/降权）→ 影子执行小回归集验证 → 应用修订。
- 对照：Mem0 写入时修订、遗忘曲线降权、无修订。
- 指标：发现召回（人工标注 gold）、修订后任务成功率、错误修订率/回归率。
- 预算：3 任务×2 漂移×20 轮；中小模型数千次调用即可完成。
